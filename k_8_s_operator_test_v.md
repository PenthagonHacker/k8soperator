# KubernetesPodOperator – Полная документация параметров (используется в этом DAG)

Этот документ содержит **полные объяснения всех параметров KubernetesPodOperator**, использованных в данном проекте.

---

## Полный пример оператора

```python
KubernetesPodOperator(
    task_id="run_test_pod",
    name="k8s-test-pod",
    namespace="airflow",
    image="python:3.11-slim",
    cmds=["python", "-c"],
    arguments=["import time; print('start'); time.sleep(20); print('end')"],
    get_logs=True,
    is_delete_operator_pod=False,
    container_resources={
        "requests": {"cpu": "250m", "memory": "256Mi"},
        "limits": {"cpu": "500m", "memory": "512Mi"},
    },
)
```

---

# 📚 Описание параметров

---

## `task_id`

**Определение:**
Уникальный идентификатор задачи внутри Airflow.

**Как работает:**
- Используется Airflow для отслеживания задачи
- Применяется в UI, логах и зависимостях DAG

**Важно:**
- Должен быть уникальным внутри DAG
- Не существует в Kubernetes

---

## `name`

**Определение:**
Базовое имя Kubernetes pod.

**Как работает:**
- Kubernetes добавляет случайный суффикс:
  ```
k8s-test-pod-<random>
```

**Где видно:**
```bash
kubectl get pods -n airflow
```

**Зачем нужно:**
- Для идентификации pod’ов, созданных задачей

---

## `namespace`

**Определение:**
Kubernetes namespace, в котором создаётся pod.

**Как работает:**
- Определяет изоляцию ресурсов в кластере
- Pod создаётся только внутри указанного namespace

**Важно:**
- Если namespace неверный → pod не создаётся

---

## `image`

**Определение:**
Docker-образ, который используется для запуска контейнера.

**Что определяет:**
- ОС
- версию Python
- установленные библиотеки

**Пример:**
```python
image="python:3.11-slim"
```

**Почему важно:**
- Отсутствие зависимостей приводит к ошибкам выполнения
- Неправильная версия окружения ломает задачу

---

## `cmds`

**Определение:**
Команда, которая выполняется внутри контейнера.

**Эквивалент Kubernetes:**
```yaml
command:
```

**Что делает:**
- Перезаписывает ENTRYPOINT контейнера

**Пример:**
```python
cmds=["python", "-c"]
```

---

## `arguments`

**Определение:**
Аргументы, передаваемые в `cmds`.

**Эквивалент Kubernetes:**
```yaml
args:
```

**Как работает:**
```python
cmds=["python", "-c"]
arguments=["print('hello')"]
```

**Результат:**
```bash
python -c "print('hello')"
```

**Почему важно:**
- Это основная логика выполнения задачи

---

## `get_logs`

**Определение:**
Определяет, будут ли логи pod передаваться в Airflow UI.

**Поведение:**
- True → логи доступны в Airflow
- False → только через kubectl

---

## `is_delete_operator_pod`

**Определение:**
Определяет, удаляется ли pod после выполнения.

**Поведение:**

| Значение | Результат |
|----------|----------|
| True     | Pod удаляется |
| False    | Pod остаётся |

**Почему важно:**
- True → используется в production
- False → удобно для отладки

---

## `container_resources`

**Определение:**
Ограничения и гарантии ресурсов для контейнера.

---

### `requests`

**Определение:**
Минимальные гарантированные ресурсы.

**Как работает:**
- Kubernetes использует их для планирования pod
- Если ресурсов нет → pod не стартует

**Пример:**
```python
"cpu": "250m"
"memory": "256Mi"
```

---

### `limits`

**Определение:**
Максимально допустимые ресурсы.

**Как работает:**
- CPU → ограничивается (throttling)
- Memory → pod может быть убит (OOMKilled)

**Пример:**
```python
"cpu": "500m"
"memory": "512Mi"
```

---

# 🧠 Единицы ресурсов

| Ресурс | Значение | Описание |
|--------|----------|----------|
| CPU    | 250m     | 0.25 ядра |
| CPU    | 1        | 1 ядро |
| Memory | 256Mi    | 256 MB |
| Memory | 1Gi      | 1024 MB |

---

# ⚙️ Поток выполнения

1. Airflow планирует задачу
2. KubernetesPodOperator создаёт pod
3. Kubernetes назначает node
4. Контейнер запускается
5. Выполняется команда
6. Логи отправляются в Airflow (если включено)
7. Pod удаляется или остаётся (в зависимости от настройки)
